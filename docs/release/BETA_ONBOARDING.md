# Beta tester onboarding

The beta validates the managed Hawelly workflow, not a self-service settlement
or custody product. Enroll only approved testers using synthetic or expressly
authorized low-value scenarios.

1. Record the tester's name, contact channel, platform, app/browser version,
   country/currency scenario, consent, and onboarding owner outside the product
   in the approved tester register.
2. Provide the official HTTPS web URL or integrity-checked Android artifact.
   Android testers must verify the published SHA-256 before installation.
3. Ask the tester to create only a sender account. Staff/admin accounts are
   provisioned separately by authorized administrators and are never created
   through public registration.
4. Walk through recipient creation, transfer request, quote review, funding
   instructions/proof, payout tracking, recipient confirmation, and dispute
   support. Staff coordinate external associates outside the app.
5. Explain that notification and timeline messages are operational status, not
   proof of bank settlement. Testers must use the displayed support/escalation
   path for any discrepancy and must not repeat a funding action without staff
   confirmation.
6. Collect the transfer reference, timestamp, platform/version, observed versus
   expected behavior, and screenshots with personal/financial data redacted.
   Never request passwords, tokens, raw database credentials, or unnecessary
   identity documents in a bug report.
7. On exit, confirm open test transfers are resolved, remove access where
   appropriate, retain required audit records, and delete off-platform feedback
   data according to the approved retention policy.

Before each cohort, operations must confirm release audit, health/readiness,
private-storage health, backup/restore evidence, staffed support coverage, and a
documented rollback owner.
